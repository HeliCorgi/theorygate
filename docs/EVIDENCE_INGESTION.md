# External evidence ingestion

TheoryGate can evaluate a model document together with evidence generated by
separate verification jobs.

This is the bridge between evidence adapters and claim promotion.

## Typical flow

Generate formal evidence:

```bash
theorygate evidence lean \
  --project ../astra-blackhole/lean \
  --id bianchi-factorization-lean \
  --obligation WDW_FACTORIZATION_ALGEBRA \
  --import AstraBlackhole \
  --theorem AstraBlackhole.time_dependent_factorization_residual \
  --output artifacts/bianchi-factorization-lean.json \
  --require-pass
```

Then ingest it while evaluating the physical claim graph:

```bash
theorygate check theorygate-model.yaml \
  --evidence artifacts/bianchi-factorization-lean.json
```

Multiple files can be supplied by repeating `--evidence` or by using a quoted
glob that TheoryGate expands itself:

```bash
theorygate check theorygate-model.yaml \
  --evidence 'artifacts/evidence/*.json' \
  --evidence 'artifacts/robustness/*.yaml'
```

Quoting the glob is recommended so the same expansion and no-match checks happen
inside TheoryGate rather than varying by shell.

## Accepted external formats

One evidence object:

```json
{
  "id": "lean-factorization",
  "obligation": "WDW_FACTORIZATION_ALGEBRA",
  "status": "PASS",
  "engine": "lean"
}
```

A list:

```json
[
  {"id": "e1", "obligation": "A", "status": "PASS", "engine": "lean"},
  {"id": "e2", "obligation": "B", "status": "PARTIAL", "engine": "scan"}
]
```

Or a bundle:

```json
{
  "evidence": [
    {"id": "e1", "obligation": "A", "status": "PASS", "engine": "lean"}
  ]
}
```

JSON and YAML are both supported.

The input path is added to each ingested record as
`metadata.theorygate_ingested_from`.

## Duplicate evidence IDs

Evidence IDs are provenance identities. TheoryGate therefore rejects duplicate
IDs by default, including a collision between inline model evidence and an
external file.

This fails:

```bash
theorygate check model.yaml --evidence new-run.json
```

if `new-run.json` reuses an evidence ID already in `model.yaml`.

Replacement must be explicit:

```bash
theorygate check model.yaml \
  --evidence new-run.json \
  --replace-evidence
```

With replacement enabled, later ingested evidence replaces the earlier record
with the same ID. This is useful for CI-generated evidence, but the flag makes
the provenance mutation visible in the command line.

## Unknown obligations

External evidence cannot invent an obligation. An ingested record whose
`obligation` is not declared by the model document is rejected.

The model controls the claim graph; evidence only attempts to discharge nodes in
that graph.

## Negative evidence

A file containing `FAIL`, `PARTIAL`, or `OPEN` is still valid evidence and
is ingested normally. TheoryGate does not discard an evidence artifact because
it blocks a desired claim.

Use `--require CLAIM_ID` when CI should fail unless promotion succeeds:

```bash
theorygate check model.yaml \
  --evidence 'artifacts/*.json' \
  --require HISTORY_PROBABILITY
```

This yields the intended pipeline:

```text
Lean / CAS / numerical scans
          |
          v
     evidence files
          |
          v
model + obligation DAG
          |
          v
   TheoryGate check
          |
          v
strongest supported physical claim
```
